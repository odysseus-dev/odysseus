## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| PR author → CI gates | Untrusted PR content crosses into the gate evaluation; gates must hard-block |
| CI install → runtime env | CI installs deps from the lock with --require-hashes |
| bandit skips → security posture | Suppressions govern which security findings are allowed to merge |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-01 | Tampering | a PR bypassing a gate that is not marked "required" | mitigate | SC#1 demonstration sets the six jobs as required status checks; deliberate-violation PR proves each blocks merge (D-01) |
| T-05-02 | Tampering | CI installing altered dependency artifacts | mitigate | All lock-consuming jobs use `uv pip install --system --require-hashes -r requirements.lock` (ASVS V10) |
| T-05-03 | Information disclosure | CI workflow over-privileged token | mitigate | `permissions: contents: read` only (no write); borrowed from the minimal doc-check convention (ASVS V14) |
| T-05-04 | Elevation of Privilege | bandit blanket-disable hiding a real high-severity issue | mitigate | Documented per-code skips with rationale only; high-severity must be fixed/triaged; recorded in security-triage.md |
| T-05-SC | Tampering | known-CVE dependency reaching main | mitigate | pip-audit job runs against the hashed lock on every PR + push:main; high/critical block or carry a documented triage |
