# Odysseus Desktop

Tauri v2 desktop wrapper for the [Odysseus](https://github.com/pewdiepie-archdaemon/odysseus) web application.

## How It Works

The desktop binary:
1. Spawns the Python server (`uvicorn odysseus.server:app`) as a child process
2. Polls `http://localhost:8000/health` until the server is ready
3. Opens a native webview window loading the SPA at `http://localhost:7000`
4. Creates a system tray icon for show/hide, settings, and quit
5. On exit, sends SIGTERM to the Python server and waits for clean shutdown

**Zero modifications** to the existing Python/JS codebase — purely additive.

## Quick Start

### Prerequisites

- **Rust** 1.77+ (`rustup install stable`)
- **Python** 3.12+ with odysseus dependencies installed (`pip install -r requirements.txt`)
- Platform deps:
  - **Linux:** `sudo apt install libwebkit2gtk-4.1-dev libappindicator3-dev librsvg2-dev patchelf`
  - **macOS:** Xcode CLI tools (`xcode-select --install`)
  - **Windows (native x86_64):** [WebView2 runtime](https://developer.microsoft.com/en-us/microsoft-edge/webview2/) (pre-installed on Windows 10/11)

### Build & Run

```bash
cd desktop

# Build (debug)
cargo build

# Run (debug, shows console on Windows)
cargo run

# Run (release, no console window)
cargo run --release
```

The binary will auto-detect your Python installation and launch the server.

### Frontend

The embedded SPA lives in `frontend/`. For now it's a placeholder `index.html`. When the actual SPA is built, copy/alias the build output here:

```
desktop/frontend/
├── index.html         ← entry point (loaded by webview)
├── assets/            ← JS, CSS bundles
├── favicon.ico
└── ...
```

```
│   ├── index.html
│   └── package.json

│   └── icon.ico
├── src/
│   ├── main.rs               ← Entry point
│   ├── lib.rs                ← App setup, commands, plugin registration
│   ├── server.rs             ← Python server lifecycle manager
│   └── tray.rs               ← System tray icon + menu
└── gen/                      ← Generated by build.rs (do not commit)
```

## Configuration

Key `tauri.conf.json` settings:

| Field | Description |
|---|---|
| `app.windows[0].url` | SPA URL (`"/"` loads from `frontendDist`, or a full URL for dev) |
| `app.security.csp` | Content Security Policy — allows `http://127.0.0.1:*` and `ws://` for server API |
| `plugins.updater.pubkey` | Public key for auto-update signature verification |
| `plugins.autostart` | Set to `null` (plugin is added programmatically with no config) |
| `bundle.windows.nsis.installMode` | `"currentUser"` (no admin required for install) |

## Auto-Update

The updater signs releases with [minisign](https://github.com/jedisct1/minisign). The signing key is **not** in the repository.

### Generate a Signing Key

```bash
cd tools/gen-key
cargo run
```

This outputs:
- `odysseus.key` — **private key** (keep secret, never commit)
- `odysseus.pub` — public key (add the base64 line to `tauri.conf.json` → `plugins.updater.pubkey`)

### CI Setup

1. Copy `odysseus.key` content into a GitHub Actions secret:
   - **Name:** `TAURI_SIGNING_PRIVATE_KEY`
   - **Value:** (entire file content, including the `untrusted comment:` line)

2. Set `TAURI_SIGNING_PRIVATE_KEY_PASSWORD` to `""` (empty) for an unencrypted key.

3. Push a tag `desktop-vX.Y.Z` to trigger a release build. The CI workflow:
   - Runs `cargo test --lib` on all 3 platforms
   - On tag push: builds platform-specific bundles (MSI, DMG, AppImage)
   - Uploads artifacts and creates a GitHub Release

### Release Workflow

```bash
git tag desktop-v0.1.0
git push origin desktop-v0.1.0
```

## Tests

```bash
cd desktop
cargo test --lib
```

Tests cover the server manager lifecycle (start, health check, shutdown). Integration tests that require a running Python server or GPU are excluded from `--lib`.

### Known Issue: `STATUS_ENTRYPOINT_NOT_FOUND` on ARM64 x64 Emulation

On Windows ARM64 running x86_64 emulated binaries, `cargo test` triggers an import of `api-ms-win-core-winrt-error-l1-1-0.dll` (specifically `RoOriginateErrorW`) which is missing on some ARM64 Windows builds. This **only** affects test binaries — the main binary runs fine.

**Workaround:** Run tests on native x86_64 (GitHub CI, or a native x86_64 machine). On ARM64, verify correctness with `cargo build` and manual testing.

## ARM64 / Cross-Compilation Notes

### Windows ARM64 → x86_64 (this machine)

Building for `x86_64-pc-windows-gnu` target under ARM64 emulation:

```powershell
# Required env vars (set before every cargo invocation):
$env:RUST_MIN_STACK = "8388608"                     # Prevents stack overflow in build scripts
$env:Path = "<llvm-mingw>\bin;" + $env:Path         # For dlltool, objdump, etc.
$env:LIBRARY_PATH = "<llvm-mingw>\x86_64-w64-mingw32\lib"  # For import libs

cargo build
```

**LLVM MinGW** provides the GNU toolchain (dlltool, etc.). Install via winget:
```powershell
winget install -e --id MartinStorsjo.LLVM-MinGW.UCRT
```

**Note:** Tauri prebuilts target `x86_64-pc-windows-msvc` on Windows. On this ARM64 machine, the MSVC toolchain is unavailable, so we use `x86_64-pc-windows-gnu` with `rust-lld` linker and `link-self-contained=yes`.

### CI (native x86_64)

CI uses `x86_64-pc-windows-msvc` (full Tauri SDK support), macOS `aarch64-apple-darwin`, and Linux `x86_64-unknown-linux-gnu`. No special configuration needed.

## Troubleshooting

| Problem | Fix |
|---|---|
| `-lktmw32` linker error | Copy `libktmw32.a` from MinGW lib dir to Rust's self-contained lib dir (`rustlib/x86_64-pc-windows-gnu/lib/`) |
| `too many exported symbols` | Remove `staticlib`/`cdylib` from `crate-type` in `Cargo.toml` — use `["rlib"]` only |
| `plugin-autostart` config error | Set `"autostart": null` in `tauri.conf.json` (plugin is added programmatically) |
| Python not found | Ensure `python3` or `python` is on PATH. The binary searches both. |
| Port 7000 in use | Kill existing uvicorn process or change the server port |
| Webview shows blank page | Check CSP in tauri.conf.json — must allow `http://127.0.0.1:*` |
| `STATUS_ENTRYPOINT_NOT_FOUND` | ARM64 emulation issue — see "Known Issue" above |

## Architecture Decisions

- **External Python process** (not bundled) — users install Python separately; avoids 100+ MB Python bundle and platform-specific packaging hell
- **`rlib` crate type only** — this is a binary application, not a library; avoids symbol export limits
- **Poll-based health check** — simpler than `AsyncRead` on stdout; server writes structured logs anyway
- **`TrayState` with `Mutex`** — Tauri v2 `TrayIcon` doesn't expose `get_item()`, so menu item handles are stored in app state
- **`RUST_MIN_STACK=8MB`** — build scripts (notably Tauri's codegen) overflow the default 2MB stack on ARM64 emulation
