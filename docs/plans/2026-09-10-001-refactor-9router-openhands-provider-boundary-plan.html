Goal Capsule

Objective: Route all agent inference in the OpenHands distribution through 9router while retaining one product frontend and one canonical agent backend.

Authority hierarchy: Rigid invariant and R1–R4 outrank every other preference. Product Contract outranks Planning Contract. Do not reinterpret or weaken R1–R4.

Product authority: Odysseus owns production experience, product policy, domain behavior, approvals, schedules, projections, entitlements, and operations. OpenHands owns agent execution, conversations, events, workspaces, and native/ACP lifecycle. 9router owns provider routing and provider credentials.

Stop conditions: Stop if a change would give Odysseus a second transcript, agent loop, or chat-completions API. Stop if Agent Server native LLM settings are treated as ACP inheritance. Stop if 9router or Agent Canvas source must be modified without evidence existing interfaces failed. Stop if Task 18 deletion is proposed in this slice.

Execution profile: Code. Overlay environment stays list form. Compose uses --pull never. Do not treat GitHub Actions as a merge gate. Do not start 9router inside the Odysseus web process.

Tail ownership: ce-work or equivalent executes units in dependency order. Abandoned-attempt code must be removed before done.

Product Contract

Product Contract preservation

Product Contract unchanged for R1–R27, A1–A6, F1–F5, and AE1–AE7. Worker-owned questions are resolved in the Planning Contract. Product scope is unaltered.

Summary

9router becomes provider authority for every inference-capable runtime distributed through OpenHands. OpenHands remains canonical agent runtime and conversation/event backend. Odysseus remains canonical production frontend and product/domain authority.

This plan covers the full product contract. Adjacent MCP expansion, Canvas features, and Task 18 deletion stay out. Test scope is the seven acceptance examples plus per-runtime fail-closed proof and the disposition ledger.

Problem Frame

Odysseus still has legacy direct inference paths while native OpenHands, OpenCode ACP, and Hermes ACP do not inherit one common provider configuration. Treating one Agent Server endpoint as universal would leave ACP inference outside the intended provider boundary.

Earlier topology rules also confused architectural purity with product value. They would have removed useful bounded inference, production connection UX, and curated model visibility even though none competes with OpenHands conversation ownership.

Key Decisions

Rigid invariant

Odysseus is canonical production and operations frontend. OpenHands is canonical agent runtime, conversation, and event backend. No other preference may override this relationship.

  • One provider authority, separate integration paths. 9router serves native OpenHands, OpenCode ACP, and Hermes ACP through runtime-specific configuration and acceptance.
  • No Odysseus conversational inference surface. Odysseus neither proxies nor accepts chat-completions APIs and does not retain a second agent loop or transcript.
  • Bounded work is not fake chat. Typed inference may use governed lightweight execution without creating a visible conversation, provided it cannot become a competing agent backend.
  • Raw catalog and secrets stay upstream. 9router owns provider/model inventory, routing, credentials, failover, quotas, and health. Odysseus may expose curated product choices and non-secret status.
  • Domain access remains separate from inference. Agents use Odysseus MCP for domain capabilities. 9router does not own MCP policy or domain behavior.

Actors

  • A1. Production user: starts and controls work through Odysseus.
  • A2. Engineer/operator: uses Agent Canvas for development inspection and raw runtime debugging.
  • A3. OpenHands runtime: owns agent execution, canonical conversation state, events, workspaces, and runtime provenance.
  • A4. ACP implementation: owns its internal model loop while OpenHands owns its outer lifecycle envelope.
  • A5. 9router: routes inference and retains provider credentials.
  • A6. Odysseus: owns product policy, domain services, MCP, ApprovalGrant authority, schedules, projections, and product UX.

Key Flows

  1. F1. Interactive work: production user submits through Odysseus; OpenHands executes canonical conversation; selected runtime calls 9router; OpenHands records events; Odysseus projects result.
  2. F2. Domain action: OpenHands agent invokes Odysseus MCP under delegated authority; Odysseus re-authorizes and executes domain behavior; result returns to canonical OpenHands event stream.
  3. F3. Bounded work: Odysseus submits typed job; governed runtime calls 9router; lifecycle and provenance remain attributable; Odysseus receives typed result without creating user-visible chat unless work is genuinely conversational.
  4. F4. Provider connection: user starts connection from allowed product surface; 9router completes provider authorization and stores tokens; Odysseus receives only opaque connection identity and non-secret state.
  5. F5. ACP execution: OpenHands launches ACP profile and owns lifecycle; ACP implementation performs internal inference through its own 9router configuration; canonical outer events remain in OpenHands.

Acceptance Examples

AE1. Shared production conversation

Covers R1–R4, R10. User sends message in Odysseus. OpenHands stores canonical conversation/events. Canvas can inspect same conversation. Odysseus stores projection, not duplicate canonical transcript.

AE2. Native provider routing

Covers R5–R9. Native OpenHands execution completes through 9router. Audit identifies runtime profile and resolved route/model. Removing 9router access causes explicit governed failure, not direct-provider fallback.

AE3. ACP provider routing

Covers R5–R9. OpenCode and Hermes each complete independent acceptance through their runtime-specific 9router configuration. Passing native OpenHands acceptance alone cannot satisfy this example.

AE4. Bounded extraction

Covers R11–R15. Structured extraction completes as governed typed work with provenance and no visible chat. If lightweight OpenHands execution fails stated needs, approved fallback worker supplies same product result without holding credentials in Odysseus web process.

AE5. Provider subscription

Covers R16–R20. User starts connection from product UX and returns with usable status. Provider tokens remain retrievable only by 9router. Odysseus can show entitlement, health, and curated route state without receiving provider secret.

AE6. Domain action separation

Covers R21–R24. Agent reasoning uses 9router, while mail, calendar, notes, documents, tasks, memory, and research operations traverse authorized Odysseus MCP capabilities rather than 9router.

AE7. Safe legacy removal

Covers R25–R27. Direct inference path is removed only after ledger names its replacement or deletion rationale and acceptance passes. Task 18 remains present while its independent hold conditions remain unmet.

Success Criteria

  • Native OpenHands, OpenCode ACP, and Hermes ACP independently prove 9router routing under real execution.
  • No production conversational inference or canonical transcript exists outside OpenHands.
  • No provider access or refresh token is stored by or returned to Odysseus.
  • Production users can operate agent work in Odysseus without using Canvas.
  • Bounded product behavior survives migration without being forced into visible chat.
  • Every removed legacy inference caller has disposition and acceptance evidence.

Key Technical Decisions

KTD1. Three independent 9router injections

Native OpenHands uses Agent Server LLM profile or persisted agent_settings.llm (base_url, virtual API key, api_mode=chat, auth_type=api_key). OpenCode uses OpenCode provider options.baseURL. Hermes uses a named Hermes providers: entry under isolated HERMES_HOME. Agent Server native LLM does not configure ACP children.

Rejected: one LLM_BASE_URL on Agent Server as universal socket. Gate 10 already showed Canvas ChatGPT subscription does not configure Hermes. Live ACP profiles currently tag acp_server: claude-code while commands are opencode acp / hermes acp; U3/U4 must correct provider detection so Anthropic env channels are not used.

KTD2. Isolated bounded-job worker, not OpenHands conversations

Pinned Agent Server 1.45 has no first-class job API. ask_agent requires an existing conversation. New conversations are listable in Canvas and would violate AE4 / AE1 product-visibility needs. R13 therefore applies now.

Odysseus submits typed jobs to a separately deployed worker. The worker calls 9router /v1/chat/completions. The web process does not hold the inference key. Reuse ModelJobExecutor; replace the raising invoke_structured_model with a worker client. The worker has no MCP client, no workspace, no transcript, and no agent profile.

Rejected: ephemeral OpenHands conversations as the primary bounded path. Rejected: calling 9router from FastAPI request handlers. A later OpenHands job primitive may replace the worker without changing the product contract.

KTD3. Owner-scoped connections and virtual runtime keys

Bind every 9router connection and every runtime virtual key to the Odysseus owner that consented. OpenHands and ACP receive a 9router virtual key, never upstream access or refresh tokens. Do not share one upstream provider credential across owners.

Rejected: a global compose OPENAI_API_KEY as the native source of truth. Rejected: org-plus-per-user combined tenancy before org identity exists.

KTD4. Fail closed outside 9router

If 9router is unreachable, unauthorized, or misconfigured, OpenHands surfaces a governed error and Odysseus projects it. No stream_llm fallback. No silent SDK default to OpenAI or Anthropic. Failover inside 9router is allowed only when the route is in that owner's policy and provenance records the resolved route.

KTD5. Configuration-only sole-provider this slice

This slice proves routing by isolated config and acceptance. Isolate ACP HOME / HERMES_HOME so host ChatGPT or Anthropic credentials cannot bypass 9router. Do not advertise ACP sole-provider as a security control until egress restriction lands as follow-up.

KTD6. Overlay configures inference; Odysseus does not PATCH provider keys

Native LLM settings, OpenCode provider files, and Hermes config are applied by the OpenHands overlay onto runtime volumes. Odysseus keeps creating conversations through OpenHandsClient without sending per-turn provider URLs or credentials.

Odysseus may read allowlisted 9router metadata paths (health, redacted providers, usage). That client must not call /v1/chat/completions. Connection UX is redirect to 9router-hosted PKCE; Odysseus stores opaque connection id and non-secret status only.

KTD7. Dual-plane runtime config

Provider config and Odysseus MCP config are separate planes. Changing 9router injection must not overwrite profile mcp:, broker credentials, or ApprovalGrant rules. Each runtime acceptance includes one 9router-backed turn and one Odysseus MCP domain call. This slice does not change mcp_servers/odysseus_server.py.

KTD8. Automatic routing plus optional curated aliases

Ordinary chat does not require an Odysseus ModelEndpoint. Default product choice is Automatic. Fast / Balanced / Best appear only when 9router aliases exist. Raw base URLs, provider keys, and model-admin screens stay out of Odysseus. Compare becomes parallel bounded jobs with resolved-model provenance, not a second chat backend.

High-Level Technical Design

Four planes exist: product, runtime control, provider, and domain MCP. Agent inference always leaves an OpenHands-owned process toward 9router. Odysseus never proxies completions.

Sequencing

  1. Phase A — U1 deploy 9router; U2 native OpenHands routing.
  2. Phase B — U3 OpenCode then U4 Hermes, each with independent acceptance.
  3. Phase C — U5 ledger; U6 worker and bounded-path migration before deleting leftover behavior.
  4. Phase D — U7 secret custody and curated UX; U8 retire leftover conversational LLM paths.

U3 and U4 must not be skipped because U2 passed. Hermes stays off the Odysseus chooser until U4 acceptance. Do not remove titles, rewrite, compare, or extract until U6 replacements pass.

Alternatives considered

  • Wait for an OpenHands job API. Rejected for this slice. 1.45 has none that meets AE4. The worker is the current R13 path.
  • Hidden OpenHands conversations for titles. Rejected. Canvas and sessions.read would see them.
  • Odysseus as 9router BFF that also completes chat. Rejected. Violates R4.
  • Egress-enforced sole-provider in this slice. Deferred. Configuration plus isolated HOME is the smallest viable proof.

RISK · MITIGATE IN U2

RISK · MITIGATE IN U3/U4

ACP bypass via host credentials or wrong acp_server

Worker becomes a second agent runtime

Token pump during connection UX
