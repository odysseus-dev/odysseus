# Манифесты миграции агентов

Odysseus должен уметь учиться у другого агента, не доверяя слепо всему его состоянию. Безопасный путь миграции:

```text
экспорт агента-источника -> адаптер источника -> манифест agent-migration.v1 -> предпросмотр -> применение
```

Манифест намеренно нейтрален к источнику. OpenClaw, Hermes, папка заметок в Markdown или любой другой агент может иметь свой адаптер, но Odysseus должен только понимать нормализованный манифест.

## Почему не импортировать всё как память?

Долговременная память должна оставаться компактной и полезной. Длинные заметки, логи, стенограммы сессий и архивы проектов — полезный контекст, но они не все являются воспоминаниями. Хорошая миграция разделяет два уровня:

- **Документы архива** сохраняют исходный материал для поиска, чтения и последующего извлечения.
- **Кандидаты в память** — это короткие факты или предпочтения, которые можно просмотреть перед сохранением в память Odysseus.

Это сохраняет существующий процесс проверки памяти Odysseus, давая ему лучший исходный материал для проверки.

## Структура манифеста

`agent-migration.v1` — это JSON-объект:

```json
{
  "schema_version": "agent-migration.v1",
  "generated_at": "2026-06-06T00:00:00Z",
  "source": {
    "name": "example-agent",
    "kind": "generic"
  },
  "summary": {
    "item_count": 3,
    "counts_by_kind": {
      "memory": 1,
      "skill": 1,
      "conversation_thread": 1,
      "archive_document": 1
    },
    "warning_count": 0
  },
  "items": [],
  "warnings": []
}
```

Каждый элемент имеет стабильный `id`, `kind`, метаданные источника и достаточно содержимого для предпросмотра импортёром перед применением.

Поддерживаемые типы элементов на первом этапе:

- `memory` — кандидат в память с `text`, `category`, `source` и метаданными provenance.
- `skill` — файл `SKILL.md` с содержимым и распарсенными метаданными frontmatter.
- `conversation_thread` — нормализованная стенограмма потока из экспортированной истории чатов. Содержимое сообщений необязательно; адаптеры могут сохранять только метаданные потока, количество сообщений, временные метки и хэши, когда манифест должен оставаться маленьким или избегать встраивания приватного текста стенограммы.
- `archive_document` — материал длинной формы. Содержимое необязательно; адаптеры могут сохранять только метаданные путь/хэш/размер, когда манифест должен оставаться маленьким.

## Создание манифеста

Используйте вспомогательный инструмент только для чтения:

```bash
python3 scripts/agent_migration_manifest.py \
  --source-name old-agent \
  --source-kind generic \
  --memory-json /path/to/memories.json \
  --skills-dir /path/to/skills \
  --conversation-json /path/to/conversations.json \
  --archive /path/to/notes \
  --output /tmp/agent-migration.json
```

Вспомогательный инструмент не записывает в `data/`, не вызывает LLM, не импортирует модули Odysseus и не изменяет источник. Он только записывает JSON.

JSON памяти может быть:

```json
[
  "Простая строка памяти",
  {
    "text": "Классифицированная память",
    "category": "preference",
    "source": "old-agent"
  }
]
```

или объектом, содержащим список под ключами `memories`, `memory`, `items` или `data`.

Навыки сканируются рекурсивно на наличие `SKILL.md`:

```bash
python3 scripts/agent_migration_manifest.py \
  --source-name hermes \
  --source-kind hermes \
  --skills-dir ~/.hermes/skills \
  --output /tmp/hermes-skills-manifest.json
```

Документы архива по умолчанию содержат только метаданные. Для встраивания текстового содержимого:

```bash
python3 scripts/agent_migration_manifest.py \
  --source-name notes-export \
  --archive /path/to/markdown-notes \
  --include-archive-content \
  --output /tmp/notes-manifest.json
```

Экспорты разговоров также по умолчанию содержат только метаданные:

```bash
python3 scripts/agent_migration_manifest.py \
  --source-name chatgpt-export \
  --source-kind chatgpt \
  --conversation-json /path/to/conversations.json \
  --output /tmp/chatgpt-conversations-manifest.json
```

На первом этапе поддерживается общий JSON разговоров, такой как:

```json
[
  {
    "id": "thread-1",
    "title": "План проекта",
    "messages": [
      {"role": "user", "content": "Мы можем это спроектировать?"},
      {"role": "assistant", "content": "Да, начнём с узкого среза."}
    ]
  }
]
```

Также распознаются экспорт `mapping` в стиле ChatGPT из `conversations.json`. Для встраивания нормализованных сообщений:

```bash
python3 scripts/agent_migration_manifest.py \
  --source-name chatgpt-export \
  --source-kind chatgpt \
  --conversation-json /path/to/conversations.json \
  --include-conversation-content \
  --max-conversation-messages 2000 \
  --output /tmp/chatgpt-conversations-with-content.json
```

Встраивание содержимого явное, поскольку экспортированные истории чатов могут быть огромными и приватными. Будущий адаптер для конкретного источника может добавить обход ZIP, метаданные вложений и специфические для провайдера поля проекта/рабочего пространства, при этом генерируя тот же элемент манифеста `conversation_thread`.

## Рекомендуемое поведение при применении

Будущий импортёр Odysseus должен относиться к манифесту как к непроверенным пользовательским данным и применять его поэтапно:

1. Показать сводку пробного запуска с количествами, предупреждениями, дубликатами и образцами элементов.
2. Создать резервную копию текущего состояния `data/` перед записью чего-либо.
3. Импортировать документы архива как документы или другой источник для поиска, а не как память.
4. Импортировать потоки разговоров как поиский архивный контекст с цитатами обратно на исходный поток. Не превращать целые стенограммы в память.
5. Показать кандидатов в память для проверки перед сохранением через обычный путь памяти.
6. Импортировать навыки только после проверки конфликтов имени/категории.
7. Пропускать секреты по умолчанию. Учётные данные требуют явных, специфических для провайдера потоков.

## Что входит в адаптеры источников?

Адаптеры могут быть специфичными для источника. Ядро манифеста не должно быть таким.

Например, адаптер OpenClaw может знать о файлах рабочего пространства OpenClaw. Адаптер Hermes может знать о `~/.hermes/config.yaml` и `~/.hermes/skills`. Адаптер ChatGPT может знать о `conversations.json`, метаданных загруженных файлов и каталогах вложений изображений. Адаптер Claude может знать о формате экспорта Claude и границах проектов. Общий адаптер может знать только о JSON памяти, JSON разговоров, `SKILL.md` и папках Markdown.

Нестандартные папки должны быть деталями адаптера, а не обязательными концепциями Odysseus.
