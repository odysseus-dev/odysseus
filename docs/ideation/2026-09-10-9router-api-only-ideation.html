Ideation: 9router / OpenHands / Odysseus boundaries

Date: 2026-09-10
Topic: 9router-openhands-odysseus-boundaries
Focus: One architecture, seven components — rigid invariant only; remaining choices follow product value and real APIs
Mode: repo-grounded

How to read this document

This is one plan with seven components, not seven competing products. The first draft ranked them as alternatives. After boundary correction they are seams of a single architecture. A later review then cut topology purity that had been treated as constitution.

The only rigid invariant is:

Odysseus is the canonical production/operations frontend. OpenHands is the canonical agent runtime, conversation, and event backend.

Everything else is replaceable: provider topology, catalog presentation, subscription UX, and how bounded jobs run.

What stays constitutional

  • OpenHands remains the exclusive canonical agent runtime, conversation, and event backend.
  • Odysseus remains the production/operations frontend and product/domain authority.
  • Odysseus does not proxy or accept chat-completions APIs, and does not own a second agent runtime or second canonical transcript.
  • 9router is sole provider authority for every inference-capable runtime in this OpenHands distribution.
  • Odysseus does not supply per-turn raw model URLs or provider credentials.
  • Provider secrets live in 9router, not Odysseus.
  • Domain MCP remains Odysseus-owned. MCP is not a 9router concern.
  • Task 18 (src/agent_loop.py) remains held until a clean disposition ledger and acceptance gates.
  • 9router stays unmodified. Canvas stays the engineering/admin surface. Odysseus does not embed Canvas.

Recommended architecture

PRODUCT PLANE
Browser
  ↔ Odysseus
     UI, product workflows, policy, approvals,
     schedules, domain services, MCP, projections,
     curated route-quality choices, non-secret connection status

RUNTIME PLANE
Odysseus
  ↔ OpenHands Agent Server / Automation
     canonical conversations, bounded runs,
     events, workspaces, cancellation, artifacts,
     profile provenance

PROVIDER PLANE
OpenHands native runtime ───────────┐
OpenCode ACP runtime ───────────────┼→ 9router
Hermes ACP runtime ─────────────────┘
                                   raw catalog, routes,
                                   credentials, failover,
                                   quotas, provider health

One provider authority is not one inherited Agent Server socket. Native OpenHands uses Agent Server LLM settings → 9router. OpenCode ACP uses OpenCode provider config → 9router. Hermes ACP uses Hermes custom provider config → 9router. OpenHands owns the ACP envelope; each ACP implementation owns its internal model calls. Each runtime is configured and acceptance-tested separately.

Optional bounded worker (only if OpenHands lacks a lightweight run that does not pollute visible chat):

Odysseus submits typed job
  → governed job worker (separate process; no 9router creds in the web process)
  → 9router
  → typed result + audit

That worker must not become a second conversation runtime.

The seven components (corrected)

1. Odysseus exits conversational LLM APIs revised

Adopt
No interactive stream_llm; no chat-completions fallback; no inbound OpenAI-compatible /v1/chat/completions; no provider-specific agent loop; no per-turn provider URL; no second transcript; no Odysseus-owned agent runtime.

Do not adopt
A ban on every bounded typed inference. A 300 ms extraction is not an agent. Forcing titles/classifiers through conversation create → workspace → agent → event stream is machinery that does not protect the invariant.

Better rule
Odysseus does not run agent loops or direct conversational inference. Agentic and conversational work executes through OpenHands. Bounded typed inference may use a governed job runtime that does not create a competing conversation or agent backend.

Bounded-job owners (ranked)
1. First-class lightweight OpenHands run/job. 2. Private/ephemeral OpenHands conversation as a migration bridge. 3. Separate governed worker calling 9router (Odysseus submits; web process does not hold 9router credentials). 4. Deletion or deterministic replacement. 5. Direct arbitrary calls from Odysseus web routes — reject.

2. One provider authority, separately injected wording rejected; intent kept

Agent Server LLM_BASE_URL=9router does not automatically configure OpenCode or Hermes. ACP llm fields are largely metrics/model-selection metadata, not credential injection.

Correct formulation: 9router is sole provider authority for this OpenHands distribution. Every inference-capable runtime launched under OpenHands must be independently configured and acceptance-tested to use 9router. Odysseus stores no copied provider schema.

AgentProfile: odysseus
  transport: native
  llm_profile_ref: 9router-native

AgentProfile: opencode
  transport: ACP
  command: opencode acp
  ACP provider config: 9router-opencode

AgentProfile: hermes
  transport: ACP
  command: hermes acp
  ACP provider config: 9router-hermes

If “sole” is security rather than convention, sandbox egress must also block ACP children from hitting provider APIs directly. Native config may be low complexity; distribution verification is medium/high.

3. One inference path; keep the control plane revised

“Two cables” omitted the required Odysseus ↔ OpenHands link. Without it Odysseus cannot submit, stream, approve, cancel, resume, or project work.

Actual planes: Browser ↔ Odysseus; Odysseus ↔ OpenHands; OpenHands-owned runtimes ↔ 9router; agents ↔ Odysseus MCP.

Better invariant
All agent inference traverses an OpenHands-owned runtime. Odysseus does not proxy chat completions or accept an OpenAI-compatible completions API.

“No Odysseus ↔ 9router” is revised to: no inference or secret-custody link. A metadata/control link is allowed if useful (health, opaque connection id, curated route list).

4. Disposition taxonomy, not “OpenHands or die” binary rejected

Existing workDestination

Webhook chatAuthenticated governed conversation/job API — not an OpenAI gateway

“OpenHands work” does not mean every task is a visible chat turn. Prefer: Odysseus submits a bounded job → OpenHands run/job id → execution through 9router → OpenHands owns lifecycle/events/provenance → Odysseus projects the product result. Implement a bounded path before removing titles, extract, rewrite, compare, or research behavior.

5. Odysseus is the production frontend wording widened

Not “policy, domain, and projection only.” Odysseus also retains production workflows, entitlements, schedule definitions, workspace privilege, approval UX and ApprovalGrant authority, artifact presentation, retry/cancel, provider-health projection where useful, bounded-job submission, and audit views.

OpenHands retains runtime, conversations/events, workspaces, native and ACP envelope, interrupt/resume, action confirmation, profile resolution, runtime provenance.

9router retains provider routing, credentials, raw catalog, aliases, failover, quotas, provider health, resolved-provider information.

6. Raw catalog upstream; curated projection allowed authority adopted

9router owns the raw provider/model catalog. OpenHands owns the executable runtime capability view. Odysseus may own a curated product projection: Automatic, Fast, Balanced, Best, Vision, Private/local, compare-these-two, route availability, quota/health, resolved-model provenance after execution.

Odysseus must not expose raw base URLs, API keys, every provider model id, low-level routing, or model-admin screens. Removing the ordinary-chat picker can be a product decision. It is not an automatic consequence of moving inference upstream.

7. Secrets upstream; connection UX may stay strongly adopt for secrets

Provider access/refresh tokens live in 9router. Upstream credentials never return to Odysseus. No token pump, no second subscription vault. OpenHands and ACP agents receive only a narrowly scoped 9router credential/configuration.

Odysseus may still own Connect, status, tenant association, entitlement, allowed routing policy, usage/quota display, disconnect, and an opaque connection id:

User starts connection in Odysseus
  → redirect to 9router-hosted authorization
  → 9router completes PKCE/OAuth
  → 9router stores provider tokens
  → Odysseus stores opaque connection ID + non-secret status

Canvas remains the engineering surface for raw provider debugging.

Reject

  • Treating Agent Server native LLM configuration as automatically inherited by ACP agents.
  • Deleting useful bounded jobs solely for topology purity.
  • Forcing every classifier/title/extraction into visible chat.
  • Sending ordinary production users to Canvas for all connection/status work.
  • Removing all model visibility because Odysseus no longer performs inference.
  • A global provider credential shared across owners without an explicit single-user constraint.
  • Direct upstream provider credentials in OpenCode/Hermes if sole-provider is meant as enforceable policy.
  • Any new Odysseus chat-completions gateway.

Suggested implementation order

  1. Deploy 9router independently; prove reachability from Agent Server and ACP execution environments.
  2. Materialize a real upstream odysseus AgentProfile (today native often uses Agent Server default).
  3. Configure native OpenHands for 9router; test conversation, tools, cancel, condensation, errors.
  4. Configure OpenCode independently; run ACP acceptance.
  5. Configure Hermes independently; run ACP acceptance.
  6. Decide whether sole-provider is configuration-only or egress-enforced.
  7. Inventory remaining direct LLM calls and classify (conversation / bounded job / deterministic / specialist / delete).
  8. Implement the bounded execution path before removing leftover product behavior.
  9. Replace raw model picker with automatic routing or curated route choices.
  10. Move credential custody to 9router; keep only opaque connection state in Odysseus.
  11. Remove legacy direct product-LLM paths.
  12. Full acceptance, then revisit Task 18.

Bottom line

Best insight: 9router serves the OpenHands distribution; it does not become another Odysseus agent backend.

Weakest assumption (now dropped): therefore Odysseus must have no model metadata, subscription UX, bounded inference path, or provider-control relationship.

Canonical relationship is protected when Odysseus owns the product experience, OpenHands owns agent execution and conversation truth, and 9router owns provider routing and credentials. Remaining choices follow product value and existing APIs, not cable-count purity.
