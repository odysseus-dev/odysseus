Tailscale Tunnel Path — Three Options

Goal: VPS can reach the Mac mini's agentmemory daemon (port 3111) over the encrypted tailnet.

Path A — Cleanest (blocked)

  • • Rebuild Hostinger container with --device=/dev/net/tun --cap-add=NET_ADMIN + iptables in image
  • • Switch tailscaled from userspace to kernel mode
  • • Direct TCP from VPS → mini over tailnet works
  • • Tunnel script already staged — flips one flag and runs
  • • BLOCKED: Hostinger containerd blocks device passthrough; no /dev/net/tun, no iptables
  • • Time to green: depends on Hostinger (days)

Path B — Sidecar (medium)

  • • Spin up a second container with /dev/net/tun, run Tailscale kernel-mode there
  • • Share the tailnet socket via a volume mount
  • • VPS gets the kernel-mode Tailscale benefits without rebuilding the main container
  • • BLOCKED: Hostinger would need to allow multi-container projects (depends on plan)
  • • Time to green: hours if allowed, never if not

Path C — Laptop ProxyJump (today)

  • • VPS opens SSH to laptop with -J tylar@100.93.33.88 as the jump
  • • Laptop relays to mini over tailnet (laptop already has kernel-mode and works fine)
  • • Tunnel terminates at VPS's localhost:3111 same as Path A
  • • Trade-off: brittle — needs laptop online. Reconnects handle brief drops
  • • Time to green: 30 min from your "go"

Why Path A is blocked (root cause)

  • • Hostinger containerd policy: docker-default seccomp profile enforces deny-by-default device access
  • • mknod /dev/net/tun c 10 200 succeeds (root has CAP_MKNOD)
  • • But open(/dev/net/tun, ...) returns EPERM — cgroup device whitelist excludes char-major-10-200
  • • iptables not installed in image — needed for kernel-mode Tailscale NAT/firewall management
  • • Even with CAP_NET_ADMIN granted, container cannot bypass cgroup device policy
  • • Hostinger would need to grant device passthrough at the orchestrator level — policy change, not config change

What works today (no tunnel needed)

  • • tailscale ping to any peer — control plane works via DERP
  • • Outbound HTTPS to login.tailscale.com, github.com, controlplane.tailscale.com
  • • All Hermes app functions (Claude Code, sessions, skills, cron)
  • • TinyFish Search + Fetch (free tier, working today)
  • • Playwright local browser harness
  • • fzf, general shell tooling

What stays blocked until tunnel

  • • AGENTMEMORY_URL=http://localhost:3111 from VPS — daemon unreachable
  • • @agentmemory/agentmemory on VPS — install script fails cleanly, waiting on tunnel
  • • Cross-machine memory continuity (your stated core goal)
  • • Any direct TCP service to the mini (only SSH via tailnet would work, and only via laptop relay)
