# Вклад в Odysseus

Спасибо за помощь. Проект движется быстро, поэтому лучшие вклады — сфокусированные, простые для ревью и простые для тестирования.

## Прежде чем начать

- Поищите среди существующих issue и pull request'ов, прежде чем открывать новый.
- Предпочитайте один багфикс или одну фичу на pull request.
- Избегайте масштабных переписываний, изменений только ради форматирования или массового перемещения файлов, если только issue не посвящён именно структуре.
- Если хотите взяться за крупную фичу, сначала откройте issue и опишите подход.

## Настройка

Docker — рекомендуемый путь для обычного тестирования:

```bash
git clone https://github.com/pewdiepie-archdaemon/odysseus.git
cd odysseus
cp .env.example .env
docker compose up -d --build
```

Ручная разработка использует Python 3.11+:

```bash
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
python -m uvicorn app:app --host 0.0.0.0 --port 7000
```

Windows активно не тестируется. Docker на Linux или ручная установка на Linux/macOS — пока более надёжный путь.

## Запуск проверок

Запускайте минимальные релевантные проверки для вашего изменения:

```bash
python -m pytest
python -m py_compile app.py routes/*.py src/*.py
node --check static/js/<файл-который-вы-меняли>.js
```

Для изменений, связанных с Docker:

```bash
docker compose config
docker compose up -d --build
docker compose logs --tail=120 odysseus
```

Укажите в описании pull request'а, что именно вы запускали. Если какую-то проверку выполнить не удалось — так и напишите.

## Pull request'ы

Хорошие pull request'ы обычно включают:

- Краткое объяснение бага или фичи.
- Изменённые файлы или области.
- Шаги ручного тестирования или результаты автотестов.
- Скриншоты или короткие записи для изменений интерфейса.
- Ссылки на связанные issue, например `Fixes #123`.

Пожалуйста, держите PR'ы небольшими. Крупные PR'ы, смешивающие несвязанную уборку, форматирование, рефакторинги и изменения поведения, ревьюить намного сложнее.

## Сообщения об ошибках (issue)

Для багов укажите:

- Способ установки: Docker, ручной Python, WSL и т.д.
- ОС, браузер и устройство, если это важно.
- Точные шаги воспроизведения.
- Ожидаемое и фактическое поведение.
- Логи, скриншоты или вывод терминала.

Для проблем с сервингом моделей укажите:

- Бэкенд: Ollama, vLLM, SGLang, llama.cpp, LM Studio и т.д.
- Название модели.
- GPU/CPU и операционную систему.
- Логи задач Cookbook или логи сервера.

Issue только с «help», «не работает» или скриншотом без контекста могут быть закрыты как неактируемые.

## Безопасность

Не публикуйте секреты, API-ключи, приватные логи, личные документы или публичные IP в issue или pull request'ах.

Для сообщений о безопасности следуйте [SECURITY.ru.md](SECURITY.ru.md).
